# 나홀로 여행자의 "심심한 순간" 동반자 앱 (v3 — 최종)

> v1(동행 매칭 중심) → v2(무드 동반자 + 라이트 동행) → v3(동행 매칭 완전 삭제, 순수 동반자 앱)으로 정리했습니다. "동행자 매칭 없이도 앱 자체가 동반자가 되어준다"는 방향으로 확정합니다.

---

## 1. 변경 이력 요약

| | v1 | v2 | v3 (최종) |
|---|---|---|---|
| 핵심 가치 | 동행자 찾기 | 무드 음악·활동 + 라이트 동행 | **무드 음악·활동만으로 동반자 역할** |
| 동행 매칭 | 핵심 기능 | 가벼운 옵션 | **없음** |
| 경쟁 구도 | 트래블어스·MOYO와 경쟁 | 애매하게 겹침 | **동행 매칭 앱과 아예 다른 카테고리** |
| 위치·프라이버시 리스크 | 큼 | 있음 | **거의 없음** |

---

## 2. 제품 개요 (PRD)

**한 줄 정의**
혼자 여행하는 사람이 심심하거나 뭘 해야 할지 모르는 순간마다, 지금 기분과 상황에 맞는 음악과 활동을 즉시 제안해 "혼자지만 혼자 같지 않게" 만들어주는 앱. 사람과 연결해주는 게 아니라, **앱 자체가 당신의 여행 동반자**입니다.

**문제 정의**
- 첫 혼자 여행자는 안전에 대한 막연한 두려움이 크지만, 한두 번 경험하면 빠르게 줄어든다.
- 반복적으로 혼자 여행하는 사람에게 진짜 남는 문제는 **"이동 중, 혼밥 중, 숙소에서 쉴 때 반복되는 심심함과 막막함"**이다.
- 기존 여행 앱은 계획·예약·동행 매칭에 집중되어 있고, 여행의 "그 순간순간"을 채워주는 앱은 없다.

**해결 방안**
- 위치·시간대·간단한 취향을 바탕으로 지금 들을 음악과 할 수 있는 활동을 질문 없이 바로 제안한다.
- 선택지를 최소화해 "결정 피로" 없이 즉시 실행 가능하게 만든다.
- 첫 여행자에게는 온보딩 단계에서 안심 가이드를 집중 제공하고, 반복 사용자에게는 최소화한다.
- 사람과의 연결은 다루지 않는다 — 앱과 사용자의 관계에만 집중한다.

**차별점**
- 트래블어스·MOYO 등은 전부 "동행을 얼마나 잘 찾아주느냐"로 경쟁하는 매칭 플랫폼이다.
- 이 앱은 애초에 사람을 연결하지 않으므로 이들과 경쟁하지 않는다. **"혼자 있는 매 순간을 앱이 채워주는 것"**이 유일한 목적이다.
- 음악은 직접 콘텐츠를 만들지 않고 스포티파이 API로 연결만 하면 되어, 콘텐츠 운영 부담 없이 시작할 수 있다.
- 위치 공유, 채팅, 신고/차단 같은 민감한 기능이 없어 프라이버시 리스크와 운영 부담이 매우 낮다.

**타겟 사용자**
- 주 타겟: 이미 혼자 여행을 한두 번 해봤고 "심심함"이 진짜 문제인 사람 (창업자 본인 페르소나)
- 부 타겟: 처음 혼자 여행을 준비하며 안전 불안이 큰 사람 (온보딩에서만 케어)

**성공 지표(안)**
- 여행 중 무드 추천 일평균 상호작용 횟수 (핵심 리텐션 지표)
- 음악 재생 완료율 / 활동 제안 클릭률
- 온보딩 완료 후 첫 무드 추천 사용 전환율
- 여행 1회당 앱 재실행 횟수 (얼마나 자주 "다시 열게" 되는지)

**리스크**
- 스포티파이·구글 플레이스 API 의존성 (요금제, 약관 변경 리스크)
- "질문 없이 바로 추천"의 정확도가 낮으면 신뢰를 잃기 쉬움 — 초기엔 추천 로직이 단순할 수밖에 없음
- 사람과의 연결 없이 순수 콘텐츠 추천만으로 장기 리텐션을 만드는 게 난이도 높은 과제 (콘텐츠 신선도, 추천 다양성 확보가 관건)

## 3. MVP 요구사항 (Requirements)

| ID | 이름 | 중요도 |
|---|---|---|
| R-PROFILE | 여행 프로필 및 설정 (경량) | high |
| R-MOOD | 무드 기반 음악 추천 | high |
| R-ACT | 주변 활동 가벼운 추천 | high |
| R-ONBOARD | 첫 여행자 안심 온보딩 | medium |

---

## 4. MVP 기능(Feature) 설계

### R-PROFILE. 여행 프로필 및 설정
**F1. 최소 정보 온보딩** — 여행지, 여행 기간, 간단한 음악 취향(장르/분위기)만 입력.
**F2. 첫 여행 여부 체크** — "혼자 여행이 처음이신가요?" 한 질문으로 온보딩 분기를 결정한다.

### R-MOOD. 무드 기반 음악 추천 (핵심 차별화 기능)
**F3. 지금 이 순간 음악 추천** — 위치·시간대·취향을 바탕으로 질문 없이 플레이리스트 1개를 바로 제시한다 (스포티파이 API 연동).
**F4. 다른 느낌으로 바꾸기** — 마음에 안 들면 한 번의 액션으로 다른 무드의 추천을 받을 수 있다.
- 미해결 이슈: 위치·시간대 외에 반영할 신호(직전 활동, 날씨 등)는 사용자 데이터가 쌓인 뒤 결정.

### R-ACT. 주변 활동 가벼운 추천
**F5. 주변 카페·볼거리 가벼운 제안** — 구글 플레이스 API로 현재 위치 주변의 카페·관광지·산책로를 간단히 제안한다. 직접 큐레이션 콘텐츠는 MVP에 포함하지 않는다.
**F6. 활동을 여행 기록에 저장** — 마음에 든 장소나 음악을 가볍게 저장해 나중에 다시 볼 수 있다.

### R-ONBOARD. 첫 여행자 안심 온보딩
**F7. 첫 혼자여행자 후기 노출** — 온보딩 중 "나와 비슷한 첫 혼자여행자"의 경험담을 보여줘 안도감을 준다.
**F8. 기본 안전 체크리스트** — 공공장소 이용, 일정 공유 등 최소한의 안전 수칙을 한 화면으로 안내한다. 반복 사용자에게는 건너뛸 수 있게 한다.

## 5. 후순위 (v2 이후 백로그 — 지금은 만들지 않음)

- 직접 큐레이션한 "혼자 하기 좋은 활동" 콘텐츠 (콘텐츠 운영 리소스 필요)
- 여행 플레이리스트 SNS 공유 기능 (사람 연결 없이 입소문 효과를 노리는 대안)
- 첫 완주 배지 등 게이미피케이션 요소
- (검토 보류) 동행자 매칭 — 프라이버시·안전·운영 부담이 커서 재도입 시 별도 논의 필요
